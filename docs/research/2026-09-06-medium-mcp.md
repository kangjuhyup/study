# Medium MCP 연동 사전 조사

## 목적과 현재 상태

주제별 Markdown 학습 기록과 로컬 이미지를 반복적으로 Medium에 옮기는 작업을 줄인다. 현재 입력 예제는 `oom-snapshot/blog/index.md`이며, 수동 붙여넣기용 `oom-snapshot/blog/medium.html`이 있다. 기존 학습 파일과 runtime pin은 보존한다.

이 문서는 구현 명세가 아닌 연동 가능성 조사 기록이다. 계정의 기존 Integration Token 보유 여부를 확인한 뒤 구현 범위를 확정한다. 토큰 값은 대화나 저장소에 기록하지 않는다.

## 공식 자료로 확인한 제약

2026-09-06 확인:

- [Medium API/Importing 안내](https://help.medium.com/hc/en-us/articles/213480228-API-Importing): 신규 Integration Token 발급과 신규 연동은 허용하지 않으며, 기존 토큰은 계속 동작한다고 안내한다. 로그인 후 직접 작성하거나 기존 웹페이지를 가져오는 방법을 제공한다.
- [공식 API 문서](https://github.com/Medium/medium-api-docs): API 지원 종료를 명시한다. 기존 문서에는 인증 사용자 조회, 글 생성 및 이미지 업로드가 있다. 글 수정 endpoint는 문서화되어 있지 않다.
- 기존 API의 글 생성 요청에서 `publishStatus`를 생략하면 기본값은 `public`이다. 연동을 구현할 경우 반드시 `draft`를 지정하고 공개 발행 기능은 제공하지 않는다.
- [Medium Rules](https://help.medium.com/hc/en-us/articles/213477928-Medium-Rules): 프로그램을 통한 자동 게시와 자동 접근을 제한한다. 브라우저 자동화를 기본 대안으로 결정하지 않는다.

문서상 지원과 계정에서 실제로 동작하는지는 별도 검증 대상이다. 이 조사에서 인증 요청, 이미지 업로드 또는 초안 생성은 수행하지 않았다.

## 계정 확인 후 결정할 방향

### 기존 토큰이 있는 경우

환경변수로 전달한 토큰을 사용해 인증 사용자 조회부터 검증한다. 성공하면 로컬 Markdown과 이미지 검증 → 이미지 업로드 → 초안 생성 → 반환 URL 저장 순서의 최소 기능을 검토한다. 저장소 전체 파일을 업로드하지 않고 지정한 글과 그 글의 이미지에만 접근한다.

같은 원문을 다시 제출할 때 기존 URL을 안내해 중복 생성을 방지한다. 수정된 원문을 기존 초안에 자동 반영하는 기능은 공식 API에서 확인되지 않았으므로 약속하지 않는다. 요청 결과가 불명확한 timeout에서는 글 생성 요청을 자동 재시도하지 않는다.

### 기존 토큰이 없는 경우

공식 API를 통한 자동 초안 생성을 완료할 수 있다고 가정하지 않는다. Markdown과 이미지를 검증하고 복사용 HTML을 준비하는 로컬 MCP를 대안으로 제시한다. 사용자는 Medium 편집기에서 붙여넣기와 저장을 수행한다. 이 대안은 자동 초안 생성과 다른 범위이므로 사용자 선택 후 구현한다.

## 다음 검증

1. 기존 토큰 보유 여부 확인. 토큰이 없다면 대안 범위 결정.
2. 선택한 방식의 입력·출력, 중복 처리, 실패 처리 및 검증 기준을 구현 명세로 확정.
3. 독립 폴더의 실행 환경과 의존성 설치 범위를 정한다. 기존 폴더의 Node 버전과 lockfile은 변경하지 않는다.
4. 선택된 방식에 맞는 로컬 변환 검증과 MCP 통신 검증을 수행한다. 외부 연동의 성공 여부는 실제 응답을 근거로 별도 보고한다.
